## Этап 1: что проверяется и меняется

Существуют постоянные inbox/outbox, транзакция сохранения сессии и ответа,
дедупликация message_id, кеш транскрипции, ограниченный повтор ИИ, проверка цитат и
принадлежности реплик, независимая проверка оценки. Изоляция индивидуальных сессий
по user_id есть; профиль компании один (АКЕНСО), изоляции нескольких компаний нет.
Семантическую справедливость оценки проверяет ИИ и ручная калибровка, схема сама по
себе её не гарантирует. При недоступной оценке баллы отсутствуют, технический дефект
не становится плохой оценкой сотрудника.

Минимальные изменения: /report НОМЕР открывает любую собственную сессию;
оплаченные попытки в SQLite; административная выдача по уникальному номеру платежа;
лимит текста 5000 символов, голоса 180 секунд/10 МБ до скачивания;
получение pending updates после рестарта вместо их удаления;
сохраняемые резервирования API и токены; отдельная операция безопасной копии SQLite.

Оплата пока ручная: `/grant ID ПОПЫТКИ ДНИ НОМЕР_ПЛАТЕЖА` только ADMIN_IDS,
после проверки поступления оплаты. Повтор номера не выдаёт ещё один пакет.
Кредит списывается на первой успешно сохранённой реплике, один раз на тренировку.
Безлимитный тариф автоматического действия не имеет: не продавать его до реализации
и проверки срока подписки. Корпоративный доступ пока выдаётся существующими ролями.

Расходы: AI_DAILY_CALLS=3000 глобально, AI_USER_DAILY_CALLS=1000 на пользователя.
SDK автоматические повторы выключены, прикладные ограниченные повторы учитываются.
AI_DAILY_USD включает бюджет в долларах; AI_PRICES_JSON — словарь model →
input_per_million/output_per_million/audio_per_minute. Без актуального тарифа
долларовая стоимость неизвестна, при включённом USD-бюджете модель без тарифа
блокируется. Неуспешные/неизвестные вызовы сохраняют консервативный резерв.
Кешированные входные токены считаются по полной цене (верхняя оценка).
Голос пока резервируется по максимуму 180 секунд; реальная длительность счёта
провайдера не подтверждена. Контроль вызовов действует и без таблицы цен.

## Резервирование и восстановление

`python -m ops.backup snapshot SOURCE NEW_BACKUP` использует SQLite backup API,
проверяет integrity_check, не перезаписывает существующий файл, права 0600.
`verify BACKUP`; `restore BACKUP NEW_PATH` восстанавливает в **новый** путь.
Для production: сначала получить проверенную копию /data/academy.sqlite3 и вынести
её за Volume; проверить доступ/шифрование/срок хранения, настроить ежедневную копию.
Для отката остановить единственный poller, проверить восстановленную базу в новом
пути, затем изменить DB_PATH на неё; оригинал сохранить. Не удалять Volume.
Копия на том же Volume не защищает от утраты Volume. Фактические backup schedules
Railway и восстановление production-данных пока не подтверждены.

## Условия продаж и поддержка

Сейчас production offline: публично продавать работающий сервис нельзя.
Перед платным пилотом: резервная копия и проверенное восстановление; один poller;
успешный деплой этой ветки в существующий сервис; реальный путь Telegram
текст/голос → диалог → разбор → повторное открытие после рестарта; два аккаунта
для проверки доступа; калибровка сильных/слабых/корректных отказов; актуальная модель
API, таблица цен и денежный потолок; контакт поддержки COMMERCIAL_CONTACT,
регламент оплаты/возврата/выдачи доступа и обработки технических сбоев.

Можно отложить: веб-кабинет, автоматическую оплату (при ручной выдаче), голос клиента,
оценку интонации, параллельные workers, PostgreSQL. Несколько компаний продавать
после company_id и проверки разграничения, сейчас поддерживается один корпоративный
контур. SQLite/один worker ограничивает нагрузку: до измерений — малый пилот.

## Неподтверждённое и доступ

Railway OAuth даёт статус/конфигурацию, но не секреты и не файлы Volume. В рабочем
окружении нет подключённых секретов и Railway CLI. Для настоящих API нужен
OPENAI_API_KEY как секрет окружения; для данных/резервной копии — CLI/SSH Railway
либо доступная копия базы; для UI-приёмки — тестовый Telegram-бот и два тестовых
аккаунта. Не запускать второй poller с production-токеном.
Изменения Railway, деплой, перезапуск, содержимое /data и реальные сообщения
пользователям в ходе этой работы не выполнялись.
