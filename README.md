# Академия продаж: release candidate 4.1

Доработанная версия развёрнута в основном production-сервисе `sales-academy-bot-v2`.
Зафиксированный release candidate: commit
`74deed3ec93ec63a04b299b4a19706eb4731927b` от 9 сентября 2026 года.

## Что изменено

Сохранены Python, pyTelegramBotAPI, OpenAI Responses API, голос → транскрипция → общий
обработчик, скрытая карточка на сессию, отдельный оценщик и восемь критериев с весами
10/15/20/15/10/10/10/10. Исходные промпты сохранены в `academy/legacy_prompts.py`;
методология итогового разбора используется новым оценщиком.

Заменены механизмы, которые не обеспечивали надёжность:

- SQLite вместо словаря в памяти; история и отчёты не стираются после завершения.
- Постоянная очередь входящих сообщений и один рабочий обработчик для демо.
- Входное сообщение, изменение сессии и очередь исходящих ответов связываются транзакцией.
- Неудачная доставка повторяется без новой генерации реплики.
- Подготовка, подтверждение, разговор, закрытый разговор и завершение — явные состояния.
- Готовность сценария определяет код по трём обязательным полям; сложность имеет значение по умолчанию.
- Прямые ответы на уточнения заполняют конкретное поле без повторного AI-интервью.
- Планировщик выбирает разрешённые факты и снятые барьеры; изменения проверяет код.
- Генератор реплики не получает полную скрытую карточку и скрытый мотив.
- Структурированная оценка проверяет веса, ID и точные цитаты. Сумму считает программа.
- При N/A общий балл /100 не пересчитывается произвольно. При дефекте симуляции итог не выставляется.
- Три бесплатные тренировки, начало списания — первая успешно обработанная реплика менеджера.
  В одной тренировке последующие реплики и повтор обработки не списывают новые попытки.

## Что увидит пользователь

/start показывает три учебные ситуации. Нажмите 1, 2 или 3, выберите уровень и нажмите
«Начать тренировку». Собственное описание также поддерживается. Готовые ситуации
вымышленные, а не подтверждённые клиенты или условия KWAY/АКЕНСО.

Можно писать или отправлять голосовые до 3 минут/10 МБ. Ответы клиента текстовые.
«Завершить тренировку» формирует и сохраняет разбор. Естественный отказ/согласие клиента
закрывает ролевую игру, после чего пользователь открывает разбор этой же кнопкой.

Команды: /start, /new, /finish, /retry, /report, /scenario, /history.
Для отчёта одной из последних десяти тренировок: `/report 123`.
/start продолжает имеющуюся сессию. /new явно оставляет старую в архиве и начинает новую.
В группах бот не работает. Голосовые ответы клиента и оценка интонации отсутствуют.

## Структура

- `bot.py`: Telegram, приём текста и голоса, рабочий цикл, доставка.
- `academy/store.py`: SQLite, входящая/исходящая очередь, сохранение и лимиты.
- `academy/engine.py`: сценарий пользовательских действий, переходы, завершение.
- `academy/domain.py`: схемы, ограничения, проверка оценки, формат отчёта.
- `academy/ai.py`: извлечение полей, карточка, планировщик, клиент, оценщик.
- `academy/scenarios.py`: три проверяемых синтетических шаблона.
- `tests/`: локальные проверки с заменой внешних API.

Это один сервис, не набор микросервисов. Веб-кабинет впоследствии может использовать
то же прикладное ядро. Для многопользовательской корпоративной платформы следующими
шагами будут: явный company_id и права доступа, версионируемые корпоративные профили,
PostgreSQL/очередь с обработкой по сессиям, резервное копирование, затем обучение и
аттестация. Сейчас профиль demo-v1 общий; настоящая изоляция компаний не заявляется.

## Локальный запуск (Linux/macOS, Python 3.12+)

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt
```

Переменные задаются через окружение процесса; файл `.env` автоматически не читается.
Не записывайте реальные секреты в репозиторий. Обязательны TELEGRAM_TOKEN и
OPENAI_API_KEY. Остальные имена и примеры находятся в `.env.example`.

```bash
.venv/bin/python bot.py
```

Локально DB_PATH по умолчанию `./data/academy.sqlite3`. На Railway нужен Volume.

## Обязательные условия перед Railway

1. Установить полный проект в отдельную ветку GitHub, сохранив исходный commit для отката.
   Новая версия состоит из нескольких файлов: замены только bot.py недостаточно.
2. Для предварительного прогона использовать отдельный тестовый Telegram-токен и
   отдельный сервис/окружение. Не запускать два poller с токеном боевого бота.
3. Подключить постоянный Volume к нужному сервису с точкой монтирования `/data`.
   Указать `DB_PATH=/data/academy.sqlite3`. Программа намеренно не стартует в Railway,
   если обнаружит, что база окажется вне Volume.
4. Команда запуска `python bot.py`, одна реплика. Изменения Railway требуют публикации
   конфигурации. Не публиковать автоматически до завершения контрольных прогонов.
5. Сохранить имеющиеся TELEGRAM_TOKEN и OPENAI_API_KEY. Настроить OPENAI_MODEL и при
   необходимости OPENAI_EVAL_MODEL на модель, действительно доступную API-проекту.
   Значение исходника `gpt-5.6-luna` оставлено как прежнее; его доступность здесь не проверена.
   Выбор модели в ChatGPT не меняет API-настройку этого бота.
6. Проверить поддержку Responses API со strict JSON Schema и транскрипции.
7. Для владельца указать Telegram ID в ADMIN_IDS, если нужен обход лимита демо.
8. Выполнить проверки из `ACCEPTANCE.md`, включая реальный текст, голос, разбор и рестарт.
9. При переключении боевого токена остановить предыдущий poller. Локальная файловая
   блокировка защищает только общий путь базы, не все сервисы Railway и чужие компьютеры.
10. После переключения проверить журналы и отсутствие 409. Не менять неактивный старый
    сервис обратно на запуск бота с тем же токеном.

В просмотренных исторических логах deployment `ddb38f03-7c95-49a7-97c9-176cd1f7fc09`
есть конфликт getUpdates 409 от 3 сентября 2026. Это подтверждает прежний конфликт,
но не доказывает его наличие сейчас. Последний просмотренный статус deployment — SUCCESS.

## Сохранность и ограничения доставки

SQLite рассчитан на один рабочий процесс демо. Volume обязателен для сохранения после
пересоздания контейнера; обычная файловая система Railway не даёт этой гарантии.
Резервные копии Volume настраиваются отдельно. Старые сессии, которые жили только в
оперативной памяти старого бота, из ZIP восстановить невозможно.

Входящие Telegram message_id дедуплицируются. Ответы сохраняются до отправки и повторно
отправляются из outbox. Если Telegram принял сообщение, а процесс упал до записи отметки
об отправке, возможен визуальный дубль. Бот не заявляет exactly-once доставку Telegram;
в истории приложения генерация и списание попытки не дублируются.

Один worker последовательно обрабатывает всех пользователей: это ограничение пропускной
способности демо. API-запросы ограничены таймаутом; параллельный корпоративный масштаб
требует очереди по сессиям. Максимум 18 торговых ходов; полная история остаётся для разбора.

## Что проверено

На 9 сентября 2026 выполнены 65 автоматических тестов стандартным unittest и компиляция
Python-файлов. Проверены перезапуск, дедупликация, последовательность, сбои, однократная
транскрипция при повторе, архив, лимиты, целостность карточки, сумма баллов, N/A, цитаты,
полная доставка длинного текста, генерация PDF и маршрут `send_document`.

Production-сборка Railway успешно прошла обязательные проверки с настоящими OpenAI API:
текстовый и голосовой сценарии, итоговый разбор, отдельная проверка оценки и длинный
диалог на 24 реплики. Сервис запущен с базой `/data/academy.sqlite3`; старые сервисы
остаются выключенными. Подробности зафиксированы в `TEST_RESULTS.txt`.

Не проверены автоматически: субъективная справедливость оценки на согласованном наборе
эталонных диалогов, фактическая доставка документа в клиентское приложение Telegram,
нагрузка, медианная стоимость и сохранность активного разговора после принудительного
перезапуска контейнера.
Промпты и ограниченный доступ к карточке уменьшают, но не исключают галлюцинации.
Ни тесты с подменой API, ни наличие JSON-схемы не подтверждают реалистичность клиента.

## Откат

Сохраните текущий commit и настройки до переключения. При неудаче остановите новый
